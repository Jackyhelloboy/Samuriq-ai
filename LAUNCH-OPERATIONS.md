# Production operations update

Production no longer serves demo workspaces or layout-preview projects. Old demo routes redirect to the real project board; no fake contributors or follow-ups are inserted. Real registration, historical agreements and financial data remain retained.

The workspace switcher is an explicit, authenticated server action. A selected view is a navigation preference, never an authorization grant. Contributor-selected Support and Notifications use the contributor layout and scoped records. Owner/manager server checks remain independent of the view cookie. The owner/manager client compatibility page is separate from the contributor's gated, one-use launch route.

Add Payments replaces the contributor payment-section label. Public page copy points to accepted settlement terms, while previously accepted policies and ledger mechanics are preserved. The owner can publish an audited, safely rendered public privacy notice and prospective role/project agreements from the policy panel. Historical receipts remain immutable.

Handles accept 3–30 lower-case letters, digits, dots and underscores, beginning/ending with a letter or digit. A database unique index resolves concurrent collisions; existing profiles receive stable member handles without changing their legal names or payment identities. The folder guide recommends these handles; existing Drive folders are not renamed automatically.

Contributors submit encrypted PNG/JPEG/WebP screenshots through a scoped, same-origin route, with streaming request limits, an 8MB file limit and a 60/hour per-account/project attempt cap. A SHA256 index atomically rejects byte-identical reuse within the project. A partial unique index rejects a second non-rejected completion/session ID for the same contributor. Corrected proofs retain the earlier rejected record. No screenshot URL is public. Contributors can read their own evidence; current assigned reviewers and authorized staff can inspect it. Review decisions are version-checked, audited, and locked once a day enters QC reconciliation. Flagged items open a private management ticket. A flagged image is a concern, not proof of fraud. Edited or different copies can evade an exact hash, so reviewers still inspect content and the client remains the source of QC.

The Hindi project now requires checked uploaded evidence from both permanent partners for every listed section before a worked-day TL record can be saved. Counts must match checked uploads. Existing records are retained. Client-required Drive copies still need upload to each person's restricted Drive folder. Automatic Google Drive permission checks, folder renaming and file synchronization are not connected; do not claim otherwise.

Each team has a per-member daily contact log with method, outcome, note, next action, actor and timestamp. TL daily contact totals are derived from unique members in that log, not arbitrary input fields. Logs are staff-entered statements, not automatic proof of calls or client activity. Client recording telemetry and client QC cannot be read without client support.

Telegram's linked community cannot be converted by unlinking the announcements channel in this run: automatic approval review rejected that action because existing comments/discussion access could be disrupted. The existing linkage was preserved. The owner phone was already hidden (Nobody), with phone discovery limited to contacts. Profile display name and bio were updated to Samuriq AI project coordination, and the existing company mark was uploaded. Bot creation/configuration and real client tutorial media remain prerequisites; no bot notifications, real client login/recording or payouts are represented as tested.
