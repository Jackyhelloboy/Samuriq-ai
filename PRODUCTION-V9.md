# Samuriq V9 · vendor operations

Client funds flow to Samuriq. For a direct contributor contract, Samuriq pays the contributor. For a vendor team, Samuriq settles the vendor and the vendor pays their members under separate private payroll agreements. The owner is the upstream vendor to the client; TL/vendor teams are downstream contractors.

The private standard project budget remains INR 250 per person per QC-approved hour (INR 500 for one shared hour with two confirmed people). This is not advertised as the personal pay offer to vendor-team members. Public cards do not disclose upstream contract rates.

New TL appointments default to vendor settlement and require private member payroll terms. Owners/managers may also appoint direct-payment coordinator teams. Existing accepted direct contracts and posted ledger entries are preserved. The owner can create a prospective vendor transition from Vendors & assignments; it cannot rewrite dates with existing project work. Members must accept new written payroll terms. Once a vendor contract exists, changing the financial period, target, upstream budget or pair format requires a new project ID; past eligibility must not be recalculated against a later project cycle.

A vendor settlement creates one protected ledger line per confirmed contributor, payable to the vendor beneficiary. It does not create duplicate contributor payouts or a separate commission on the same vendor work. Client QC is mandatory. The snapshotted target (for example 14 approved pair hours) must be met before posting a vendor settlement; zero means QC-only eligibility. Pair hours count once toward the shared target, while approved value includes both people. The owner can aggregate all unclaimed posted vendor work for a closed month into one bank-transfer order. Each source earning is claimed exactly once in payout_items, preventing an additional individual payment for the same work. Existing single-order claims are backfilled. Bank details remain self-owned and owner-private. Vendors cannot read their members' bank accounts.

Each leader is limited to one active project unless an owner/manager records a higher limit and separately appoints the extra team. Limits are enforced in team/evidence/contact/export/support authorization and direct routing. Cross-team query parameters never grant access. Vendor changes to default payroll terms affect new joins and unaccepted offers only. Accepted member agreements are frozen.

The Hindi recording project opens enrollment for the existing 18 November 2026 deadline. The owner chose to configure real tutorial and Telegram links later. If either is missing, work stays explicitly locked. Managers add links through Project workflow; after completed/verified tutorials and accepted terms, a server-gated community redirect opens the configured invite. No Telegram channel is created or claimed connected before a real invite is supplied. Drive playback still requires coordinator verification.

All role demos are isolated synthetic previews at /demo/login with no password or live permission. Real account passwords are never disclosed or shared; real roles must be granted to separately registered people.

Team activity queries are scoped in SQL to the assigned team, with project/status and team-member indexes. Tables paginate 50 members. New public readiness output contains booleans only. robots.txt and sitemap.xml address the missing crawler routes observed in production logs. Local concurrency tests do not establish a production capacity guarantee. Payment-provider credentials and provider acceptance testing are still required before Cashfree live transfers.
